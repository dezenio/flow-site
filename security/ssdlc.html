Flow

Secure Software Development Lifecycle

Dezenio, LLC · Effective November 11, 2026 · Reviewed at least once a year

Scope

How Dezenio designs, builds, tests and releases Flow, the native app for macOS, iOS, iPadOS and watchOS. Flow has no server component: it runs on the user's devices and connects directly to Microsoft 365, Zoom and Anthropic with the user's own credentials.

1. Design

  • Significant design choices are recorded as decision documents in the repository (for example, keeping all processing on the user's device with no Dezenio servers).
  • Each new connection or permission is reviewed for least privilege: Flow asks only for delegated, user-level scopes it uses, and every scope is listed with its purpose.
  • Privacy by design: user data stays on the user's devices and in their own storage; Dezenio does not receive it.

2. Development

  • Source code lives in a private GitHub repository. Each change is made on its own branch and merged only after review and a passing build.
  • Code is written in Swift with Apple's frameworks only; no third-party packages are included (see the Dependency Management Policy).
  • Secrets never go in source code. Users' tokens and API keys are stored only in the device Keychain. Identifiers in the code (app and client IDs) are public values, not secrets. Before each commit, changes are checked for secret patterns (such as API key prefixes).
  • Network traffic uses HTTPS with TLS 1.2 or higher, enforced by Apple's App Transport Security with no exceptions. OAuth sign-in uses the authorization code flow with PKCE; no client secrets are shipped in the app.
  • AI-assisted code changes are reviewed by the developer before merging, like any other change.

3. Testing

  • An automated test suite (over 1,200 tests) covers models, storage, sign-in, sync and each connection. It runs before changes are merged and before every release.
  • Tests are isolated from real user data: they run against throwaway settings and files, and a dedicated test fails the suite if that isolation is ever broken.
  • Static application security testing (SAST) with Semgrep runs on the codebase before each release. Findings are triaged under the Vulnerability Management Policy.
  • Dynamic application security testing (DAST) with OWASP ZAP runs against Flow's public web pages before they change and at least every six months.

4. Release

  • Builds are signed with Dezenio's Apple Developer certificates and distributed through Apple (TestFlight and the App Store), which applies Apple's review and notarization.
  • Each release goes to testers through TestFlight before wider release, with notes describing what changed.
  • Signing keys and the App Store Connect API key are kept on the developer's machine only, never in the repository or shared.

5. Maintenance

  • Bugs and security issues are logged and tracked to resolution in the project's issue log.
  • Security reports are handled under the Vulnerability Management and Incident Response policies.
  • Changes to the APIs Flow uses (Microsoft Graph, Zoom, Anthropic, Apple) are monitored and handled as part of normal releases.
